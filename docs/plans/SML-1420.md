# SML-1420 — MCP Update Notification

**Title:** Prompt or auto-update MCP registration after extension update
**Scope:** small-medium (2 new files, 2 modified files)
**Branch:** marc/sml-1420-prompt-or-auto-update-mcp-registration-after-extension
**Design decision:** Approach B — per-entry `{ scope, installedVersion }` records in workspaceState (local/project scope) or globalState (user/global scope), one per agent. Notification on activation when any record is outdated; 1 agent → specific button, 2+ → "Update All".

## Overview

New `mcp-install-state.ts` module provides three helpers:
- `recordMcpInstall(context, agent, scope, version)` — writes after each setup command succeeds
- `getMcpInstallRecords(context)` — reads all six slots (claude/cursor/codex × workspace/global)
- `getOutdatedMcpInstalls(context, version)` — filters to entries with version mismatch

`setupClaude`, `setupCursor`, `setupCodex` are refactored to extract their "do the setup" logic into inner helper functions (`applyClaudeSetup`, `applyCursorSetup`, `applyCodexSetup`), each calling `recordMcpInstall` on success. A new `agenticBookmarks.updateMcpRegistrations` command calls these helpers using the stored scope, without re-prompting.

On activation (fire-and-forget, after command registration), `getOutdatedMcpInstalls` is checked. If any entries are stale, `showInformationMessage` is shown with an "Update [Agent] (scope)" or "Update All" button that executes `agenticBookmarks.updateMcpRegistrations`.
