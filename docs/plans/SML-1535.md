# SML-1535 [F-024]: Claude install state recorded as success regardless of whether `claude mcp add` succeeded

`applyClaudeSetup`/`applyClaudeSetupAll` fire `claude mcp add` via `terminal.sendText(cmd, true)` (fire-and-forget) then unconditionally `recordMcpInstall(..., currentVersion)`. If the `claude` CLI is missing or the add fails, Claude is still recorded installed — the Agent Connections panel shows it connected, outdated/smart-update treat it as installed, update-all silently no-ops into an unwatched terminal, and a later uninstall does nothing meaningful. Cursor/Codex don't have this bug: they write their own config via `fs.writeFile` and record only after the write resolves (the same asymmetry called out in SML-1518/F-007, where Claude was "immune" *because* it delegates to the CLI — which is exactly what makes its success unobservable here).

**Approach — reconcile against `claude`'s own config.** The terminal is fire-and-forget, so there is no exit code to gate on. Rather than re-run `claude` via `child_process` (VS Code's extension host frequently lacks the user's shell PATH → false negatives that block real installs) or thread a `pending` flag through every install-state consumer (panel "connected" check, `isOutdated`, smart-update, update-all, row-actions — wide and pointless without a confirmation signal), we read the artifact the CLI produces: `~/.claude.json`. Verified layout on disk — user scope → top-level `mcpServers.agentic_bookmarks`; local scope → `projects[<terminal cwd = workspace root>].mcpServers.agentic_bookmarks`.

**Fix.** New pure, dependency-injected helper `mcp-claude-verify.ts` (mirrors the `applyCursorInstall`/`FsDeps` inject-and-return-a-verdict pattern):
- `evaluateClaudeInstall(read, scope, projectPath, serverId?) -> 'confirmed' | 'absent' | 'inconclusive'`. Entry present → `confirmed`. Config readable (incl. **file-missing/ENOENT**) but no entry → `absent` (CLI missing or add failed). Config unreadable (parse/permission error) → `inconclusive`.
- `verifyClaudeInstall({ readConfig, sleep, scope, projectPath, attempts?, delayMs? })` — the `claude mcp add` runs async, so poll a few times; return `confirmed` as soon as seen, else the final verdict (injected `readConfig`/`sleep` → no real fs/timers in tests).
- `readClaudeConfig(readFile, homeDir?)` — ENOENT/ENOTDIR → `{config:null}`; other error or corrupt JSON → `{unreadable:true}`.

`applyClaudeSetup` now records only on `confirmed`/`inconclusive` (the latter degrades to today's behavior so a momentarily-unreadable config never regresses); on `absent` it records nothing and shows an actionable "couldn't confirm — check the terminal / install the `claude` CLI" warning. `applyClaudeSetupAll` verifies each requested scope in parallel and returns the unconfirmed scopes; `applyAgentSetupAll` counts those as `failed`, so smart-update / update-all report accurately instead of silently no-opping. The record shape and all its consumers are untouched; a confirmed install behaves exactly as before. The terminal-driven limitation (and the workspace-cwd assumption for local scope) is documented on `applyClaudeSetup`.

**Files:** `packages/extension/src/commands/mcp-claude-verify.ts` (new), `mcp-claude-verify.test.ts` (new — `evaluate`/`verify`/`read` cases incl. ENOENT-absent, project-isolation, inconclusive-degrade, early-confirm), `mcp-config-and-diagnostics.ts` (`applyClaudeSetup`/`applyClaudeSetupAll`/`applyAgentSetupAll` wiring + doc comment).
**Scope:** small. No core / DB / env / dependency changes. Baseline 821/821 + typecheck + lint stay green.
