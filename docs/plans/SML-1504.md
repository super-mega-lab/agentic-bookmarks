# SML-1504: Restart file watchers on registry change so MCP-created files are watched without reload

Files added to the registry via MCP (`file_create` / `file_register` / `group_create`) while VS Code is
open got no pulse/data watcher, so later writes to them never triggered `revalidateAndRepaint` — stale UI
until a window reload. The registry `onChange` handler invalidated the cache and refreshed trees but never
rebuilt the per-file watcher set.

- **(a)** Call `restartWatchers()` from the registry `onChange` handler (after `invalidateRegistryCache`,
  before the tree/decoration refresh) so a fresh `readRegistry` rebuilds pulse/data watchers for every
  enabled file — including newly-registered ones. The existing 150ms debounce guards against thrash.
- **(b)** Fix batch disposal so the rebuild doesn't double-watch. `setupWatchers` previously kept only the
  *first* created watcher (`fsWatcher = disposables[0]`), so a restart disposed only that one and leaked the
  rest. Track all per-file watchers in a `fileWatchers: Disposable[]` array, dispose the whole batch on
  restart, and register one umbrella disposable in `context.subscriptions` (instead of pushing each watcher,
  which would grow unboundedly on repeated restarts). This satisfies "existing files aren't double-watched".

`restartWatchers` rebuilds only the per-file (pulse/data) watchers, not the registry watcher, so there is no
self-retrigger. Manual repro: with the extension running, MCP-create a file + add a bookmark to it → tree and
decorations now update with no reload. Covered by two new `watchers.test.ts` regression tests.
