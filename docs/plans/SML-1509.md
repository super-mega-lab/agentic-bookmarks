# SML-1509: broken-anchors cache `coveredUris` grows unbounded over a workspace's lifetime

`coveredUris` in `.bookmarks/local/broken-anchors.json` is appended via `mergeCoveredUris`
(`scanValidate.ts` — a pure `[...new Set([...existing, ...added])]` union) on every cache write and
never pruned. URIs for files that are deleted, deregistered, or no longer have any bookmark stay in
the set forever, so it grows monotonically and bloats the file. The coverage *number* is unaffected
(the server intersects `coveredUris` with `index.universe` in `anchor-git.ts`), so impact is
file-size/serialization growth only — Low.

- **Fix (ticket's primary suggestion):** at both write sites, after the existing union, intersect
  `coveredUris` with the live bookmark "universe" — the set of every enabled registry file's target
  URIs, fragment-stripped — mirroring how the server builds `index.universe`.
  - `scanValidate.ts`: new pure `pruneCoveredUris(coveredUris, universe)` — keeps only covered URIs
    whose `split('#')[0]` form is in the universe (fragment-insensitive, matching server coverage).
  - `brokenAnchorsSync.ts`: new `collectBookmarkedUris(workspaceRoot, registry)` →
    `{ uris, reliable }` (reads enabled data files via `readFileV2`); prune the merged set in
    `syncBrokenAnchorsCache` (the 1s-debounced open/repair path).
  - `extension.ts`: prune the merged set in `writeAuthoritativeScanCache` (the Scan-All path).
- **Conservatism:** `collectBookmarkedUris` sets `reliable: false` if any data file fails to read;
  the prune is skipped then (and when no registry is available), so coverage is never dropped for a
  file whose data is momentarily unreadable — mirrors the server's `loadError` behavior. Both
  `openRelUris`/`scannedUris` are already in the universe, so pruning only removes carried-forward
  stale entries.
- **Why not fs.stat each covered URI (ticket's secondary suggestion):** only handles the
  deleted-file cause, not deregistered / un-bookmarked (2 of 3 causes), and adds an `fs.stat` per
  URI vs. one cache-backed registry read. Extension-only; no core/server changes.
- **Tests:** pure `pruneCoveredUris` unit tests (drop/keep/fragment-insensitive/empty) in
  `scanValidate.test.ts`; temp-fs `collectBookmarkedUris` tests (enabled-only, fragment-stripped,
  `reliable:false` on read error) in new `brokenAnchorsSync.test.ts`.
