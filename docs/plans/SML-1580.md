# SML-1580: Fix standalone server BOOKMARKS_DIR / BOOKMARKS_UPWARD_DISCOVERY bootstrap

**Scope:** Small · **Files:** workspace.ts + index.ts · **Tests:** workspace.test.ts additions

## Root Cause

The extension config writers set `BOOKMARKS_DIR=…/.bookmarks/local` for per-project scope and `BOOKMARKS_DIR='' + BOOKMARKS_UPWARD_DISCOVERY=true` for global scope. The bootstrap honors neither:

- `parseWorkspaceConfig` fallback uses `BOOKMARKS_DIR` directly as workspace root → `readRegistry(…/local)` doubles the path to `…/local/.bookmarks/local/bookmarks.registry.json`
- `findWorkspaceRootUpward` is defined but never called; `BOOKMARKS_UPWARD_DISCOVERY` is ignored

## Fix

1. **`workspace.ts`**: Add private `localDirToWorkspaceRoot(dir)` (strips `.bookmarks/local` suffix) + exported async `resolveBootstrapRoot(env, cwd)` (handles both env var patterns). Fix `parseWorkspaceConfig` fallback to accept optional `standaloneRoot?: string` param.

2. **`index.ts`**: Call `await resolveBootstrapRoot(process.env)` before `parseWorkspaceConfig`, pass result as `standaloneRoot`. Reuse in the `ctx.workspaces.length === 0` branch.

## Tests Added (workspace.test.ts)

- UPWARD_DISCOVERY → walks up to find registry
- UPWARD_DISCOVERY + no registry → cwd fallback
- BOOKMARKS_DIR ending in `local` → strips 2 levels
- BOOKMARKS_DIR not ending in `local` → uses as-is
- Neither env var → cwd
