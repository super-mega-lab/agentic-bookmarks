# SML-1569 — Extension runtime robustness (trim plan)

Four loosely-coupled extension-side robustness items split from SML-1562 (post-0.8.19 review). All in `packages/extension/src`; no core changes.

1. **onError robustness (code fix, SML-1532 residual):** wrap `options.onError(err)` in try/catch in `scoped-activation-guard.ts` (honor the never-rejects contract); log `err.stack` not just `err.message` at `extension.ts:181`. Test: onError-throws case in `scoped-activation-guard.test.ts`.
2. **Watcher-set disposal guard (code fix, SML-1540 residual):** add a `disposed` flag to `createWatcherManagerSet` (the per-folder manager already had one) so a `sync()` after `dispose()` can't re-create leaked FileSystemWatchers. Test: "sync() after dispose() creates no new watchers" in `watchers.test.ts`.
3. **Multi-change-per-event sticky test (test gap, SML-1539 residual):** add tests to `sticky.test.ts` for a single event carrying 2+ content changes (multi-cursor / replace-all); guards the realistic delta-0 case, documents the line-shift coordinate limitation.
4. **Broken-anchors shared-mutex guard test (test gap):** new `broken-anchors-mutex-guard.test.ts` — source-scan tripwire that both `debouncedCacheSync` and `writeAuthoritativeScanCache` route through the one shared `brokenAnchorsCacheMutex`, plus a behavioral `AsyncMutex` non-interleaving test.
