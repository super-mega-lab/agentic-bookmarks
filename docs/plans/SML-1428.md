# Plan: SML-1428 — Expand welcome panel and collapse others when setup is incomplete

## Overview

First-install UX fix. VS Code has no API to dynamically collapse sidebar panels at runtime, but the `"visibility"` property on view contributions sets the initial state when a user first installs the extension (before VS Code has remembered any preference).

Currently the three non-welcome views have no `"visibility"` set → they default to expanded on first install. Adding `"visibility": "collapsed"` makes first-time users see the welcome panel prominently and the other panels collapsed. Returning users are unaffected because VS Code remembers their preference after first use.

## Approach Decision

**Only viable approach**: Package.json `"visibility": "collapsed"` on the 3 non-welcome views.

Rejected alternatives:
- `view.show()` from extension code: can expand a view but cannot collapse others — doesn't solve the problem
- `when` clause conditions: can hide/show views but doesn't support collapse/expand at runtime
- Context-key based dynamic collapse: VS Code doesn't honor context-key changes for view collapse state

## Test Strategy

Add a configuration integrity test to `welcomeView.test.ts`:
```typescript
describe('view contribution visibility', () => {
  it('non-welcome views start collapsed so the welcome panel is prominent on first install', () => {
    const pkg = JSON.parse(fs.readFileSync(path.join(__dirname, '../../../..', 'package.json'), 'utf8'));
    const views = pkg.contributes.views['agenticBookmarks-container'];
    const nonWelcome = views.filter((v: any) => v.id !== 'agenticBookmarks.welcome');
    for (const view of nonWelcome) {
      expect(view.visibility, `view ${view.id} should be collapsed`).toBe('collapsed');
    }
  });
});
```

## Risk Assessment & Edge Cases

- **Returning users**: VS Code remembers panel state after first interaction. Package.json visibility only applies when no stored state exists. Safe for existing users.
- **No folder case**: Workspace-scoped activation is deferred (SML-1394), so tree views aren't even created until a folder is opened. Welcome view is already the only panel → no change needed for this case.
- **Package.json validity**: JSON change only. No TS compilation required. Risk: very low.

**Before**: Fresh install opens the extension sidebar → 4 panels all expanded. Welcome is buried under three expanded tree views. User can't see the onboarding content without scrolling.

**After** (NEW): Fresh install → welcome panel expanded (UNCHANGED — already `"visibility": "visible"`), other 3 panels start collapsed (MODIFIED — now `"visibility": "collapsed"`).
