# SML-1500: Harden all onFileOpened call sites against a single failing document

SML-1495 only guarded `revalidateOpenDocuments`; the other `onFileOpened` paths are still bare
`await` — the startup scan (throw → aborts the loop → rejects `activate()`) and the
active-editor/save handlers (throw → skips `updateDecorations()` + unhandled rejection). Move the
guard down to the single choke-point everything funnels through.

- **Fix:** Wrap the body of the **internal** `onFileOpened` (`anchor-resolution.ts`, destructured in
  `extension.ts` as `rawOnFileOpened`) in try/catch + `log.error`, making it **never-throw for all
  callers** — startup scan, open/active/save handlers, and the `revalidateOpenDocuments` loop. The
  guard must live in the internal fn (not just the `extension.ts` wrapper) because
  `revalidateOpenDocuments` calls it directly.
- **Cleanup:** Remove the now-redundant SML-1495 per-loop try/catch in `revalidateOpenDocuments` and
  its now-unused `const docUri` local. `repaintAfter`'s guard (SML-1496) becomes belt-and-suspenders.
- **Tests:** Add coverage for a `getText()`-throwing document and the `scheme !== 'file'` /
  `!hasStateForFile` continue-guards. Existing SML-1495/1497 tests stay green (now exercising the
  relocated guard).

**Files:** `packages/extension/src/anchor-resolution.ts`, `packages/extension/src/anchor-resolution.test.ts`
(no `extension.ts` edits needed — all five paths reach the internal `onFileOpened`)
**Scope:** small (2 files, behavior-preserving except error handling)
**Branch:** `SML-1500/harden-onfileopened-call-sites`
