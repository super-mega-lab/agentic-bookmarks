# SML-1553 — renamed_chain content-similarity confidence

**anchor_traceLineHistory renamed_chain pairs lines by position only → high-confidence false repair.** Server-side fix; agent-facing result only (no auto-repair consumer).

## Problem
After core dead-ends at `status:'deleted'` for a grouped hunk, `findSamePositionReplacement` (`packages/server/src/anchor-git-tools.ts`) pairs the bookmarked deletion with the same-run-index addition, gated only on leading-whitespace + non-blank. An unrelated block added in place (`const apple = computeApple();` → `const zebra = loadZebra();`) is emitted as `renamed_chain` at `confidence:'high'`.

## Decision (maintainer checkpoint)
**Demote-only — no hop-dropping floor.** `tokenFuzzyScore` measures *reshape* similarity, not *rename* similarity, so it can't distinguish SML-1468's legit fully-renamed functions from the bug. Rather than drop hops (which would gut SML-1468's rename-following), keep every hop and demote confidence based on content similarity.

## Fix
- Reuse core `tokenMatch.tokenFuzzyScore(deleted, replacement, { language })` (the scorer already used for `bodySimilarity`); derive `language` from `comments.getLanguageForPath(targetRelPath)`.
- `findSamePositionReplacement` returns the per-hop `similarity`; the follow-through loop tracks `minHopSimilarity`.
- New `renameChainConfidence(chainLength, minSimilarity)`: `minSimilarity < 0.5` → `'low'`; else `chainLength <= 3 ? 'high' : 'medium'`. Applied at both `renamed_chain` emit sites.
- Soften the repair-skill-guide string: `low` ⇒ positional guess, verify `finalContent` before repairing, never auto-repair.

Calibration (language-weighted): apple→zebra ≈0.02, full rename ≈0.05, same-name reshape ≈0.52–0.92 — wide gap around the 0.5 boundary.

## Tests (`trace-line-history.test.ts`)
- NEW: grouped unrelated replacement → `renamed_chain` `confidence:'low'`, `finalContent` is the (wrong) paired line (bug repro).
- NEW: grouped same-name reshape → `confidence:'high'` (strong reshape still trusted).
- UPDATED: two existing rename tests' `confidence` assertions `'high'` → `'low'` (those fixtures fully rename the identifier; high was the bug).

## Preserved invariants
No-hop `deleted` result byte-identical; pure deletions stay `deleted`; SML-1468 follow-through (renamed_chain still emitted, 0-based conversion, off-by-one fix) unchanged.
