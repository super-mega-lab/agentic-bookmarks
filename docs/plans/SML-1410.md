# SML-1410 — Implementation Plan

**Title:** Add Open / Scan all files containing bookmarks commands
**Scope:** medium (3 modified, 3 new — 6 files)
**Branch:** SML-1410/bulk-open-scan-commands
**Design decision (Phase 2):** Two helpers split (visible vs all-registered) + one shared open/scan runner + one command file registering all four commands. Helpers are pure and unit-tested; runner is the only place vscode `openTextDocument` / `showTextDocument` is called.

## Overview

Add 4 new commands that load every file containing bookmarks:

- `agenticBookmarks.openAllFiles` — opens visible-bookmark files as non-preview background tabs
- `agenticBookmarks.openAllFilesIncludingHidden` — same as above, but covers every registry-enabled bookmarked file regardless of UI visibility
- `agenticBookmarks.scanAllFiles` — `workspace.openTextDocument` only (no tabs); triggers anchor validation/decoration as a side effect
- `agenticBookmarks.scanAllFilesIncludingHidden` — same as above with the broader scope

Visibility semantics mirror the existing pair convention: the plain variants match `listAll`/`export` (UI visibility honored when `filterEnabled` is true); the `IncludingHidden` variants match `clearAll` (only `enabled !== false` registry filter, no UI filter).

All four commands share a single runner that:
- Iterates targets in stable alphabetical order (`relativePath`).
- Wraps the loop in `vscode.window.withProgress({ location: Notification, cancellable: true })` when count > 5.
- Open mode: `openTextDocument` then `showTextDocument(doc, { preview: false, preserveFocus: true, viewColumn: ViewColumn.Active })`.
- Scan mode: `openTextDocument` only.
- Skips files that fail to load, surfaces the failure count in a non-modal info message.

No keybindings (deferred per ticket). No new settings. No menu changes. `activationEvents` stays at `["onStartupFinished"]`.
