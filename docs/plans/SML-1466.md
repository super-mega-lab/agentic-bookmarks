# SML-1466: anchor_getFileDiff detects merged functions as a semantic successor

When two constructs are **merged** (one method/setter/function's body combined into another in the same
commit), the repair waterfall returned only negatives (`no_match`, trace `deleted`) and the agent declared the
deleted bookmark non-repairable — even though the deleted logic still lives inside the surviving method, whose
added/expanded body is right there in the diff.

- **Fix:** add a pure `detectMergedConstruct(anchor, diff, currentFileLines)` and run it inside
  `handleGetFileDiff` **only when** core's `diagnoseDiff` returns `no_match` **and** the SML-1465
  `detectInlinedConstruct` did not already claim it (chain inlined → merged). On a hit it replaces the
  diagnosis with `{diagnosis:'merged', detail:{deletedSymbol, deletedKeyLines, mergedInto:{line,content,symbol,confidence},
  candidates[], explanation}}` pointing the agent at the merged method's **declaration** line. One enclosing
  method → `medium`; key fragments scattered across several new methods → `low`; none found → returns null
  (stays non-repairable). Purely additive — every other diagnosis path (and `no_match` without a merge) is
  byte-for-byte unchanged.
- **Merged vs inlined (same mechanic, different target):** inlined matches a *single-statement* deleted body at
  a **call site** (exact / param-template, whole line). Merged matches the deleted body's *multiple key
  expressions* as added lines **inside another function definition**, using substring **containment** to
  tolerate reflow (the example's `this.emit(...)` is reformatted across lines in the merged method). The
  enclosing method is found by walking up `currentFileLines` from a matched added line to the nearest
  declaration. Shared pure helpers (`parseDeclaration`, specificity/template guards, `declTiedToAnchor`, …) are
  exported from `inline-detection.ts` and reused — no duplication, SML-1465 behavior unchanged.
- **Why tool-level in this repo:** mirrors the landed SML-1465 design — the diagnosis enum lives in sibling
  core's `diagnoseDiff`, but the server handler already holds the full net diff (deletion + the merged-method
  additions for the same-file case), so detection is a self-contained server post-process. No cross-repo core
  change.

Conservative to avoid misleading the agent: only on `no_match`, declaration must tie to the anchor, only
specific body fragments are searched, an enclosing declaration is required (distinguishes merged from a bare
call site), param renaming tolerated, null on ambiguity. Out of scope (return null): cross-file merges,
multi-commit merges, complete rewrites where no body fragment survives.
