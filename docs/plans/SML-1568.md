# SML-1568 — Anchor trace/diagnosis cleanup + repair skill-guide sync

Post-0.8.19 cleanup (parent SML-1562). Six items; item 3 expanded to a cross-repo core+server change by decision.

## What changed
1. **Unify trace field** — `renameChain` (deleted path) → `chain`, matching the `renamed_chain` result + a new rename-then-deletion test. (`anchor-git-tools.ts`)
2. **MAX_HOPS** — return the partial `renamed_chain` at the 25-hop cap instead of degrading to `trace_invalid`; drop the unreachable `if (chain.length === 0) break`. (`anchor-git-tools.ts`)
3. **Follow file rename mid-sequence** *(cross-repo)* — core gains an opt-in `trackRenames` on `getPatchSequence` (per-commit path map + `-M` diff) and evolving-path tracking in `traceLineThroughPatches`; the server trace opts in and tracks the path in its deleted-branch follow-through loop. Additive: `trackRenames:false` is byte-identical, so `auto-repair` is unaffected. (core `git-history/{types,log,trace}.ts` + server `anchor-git-tools.ts`)
4. **merged-detection** — tighten the over-broad self-merge guard; memoize `findEnclosingDeclaration` (was recomputed per fragment-match). (`merged-detection.ts`)
5. **inline-detection** — bound `bodyDeletionLines` at the first brace-only line (sibling-consistency with merged); add a point-anchor positional-fallback test. (`inline-detection.ts`)
6. **Skill-guide sync** — add `inlined`/`merged` (+`signature_changed`) to the Available-Tools quick-list and the diff-analysis waterfall step; note the partial chain on a `deleted` result. (`getRepairSkillGuide`)

## Delivery
Two PRs: agentic-bookmarks-core (items affecting trace pipeline) first, then agentic-bookmarks server. Rebuild core dist between.

## Risk
Item 3 touches the load-bearing trace pipeline (repair + auto-repair). Controlled by the opt-in flag + full core+server suites against baseline (server 159 tests green pre-change).
