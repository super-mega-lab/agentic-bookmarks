# SML-1468: anchor_traceLineHistory follows multi-hop in-place renames (renamed_chain)

When a symbol is renamed across ≥2 commits (A→B→C), the trace was expected to dead-end at `status: "deleted"`.
Characterizing the actual behavior first showed a subtler truth: core's `traceLineThroughPatches` *already*
follows a rename when the deleted line is **immediately** followed by its replacement addition (→ `modified` →
resolves as `traced`), so clean single-line renames already work. The real gap is **grouped hunks** — when the
bookmarked line changes together with an adjacent line, git emits all `-` then all `+`, so the bookmarked deletion
is followed by another deletion and core returns `deleted`, stopping at the first rename hop.

- **Fix (server-only):** in `handleTraceLineHistory`, when the trace dead-ends at `deleted`, a new
  `findSamePositionReplacement()` looks in the deletion hunk for an added line at the same position-within-the-
  change-block with matching indentation. If found, record a rename hop, advance to the replacement's line, and
  re-run `traceLineThroughPatches` over the remaining patches; loop for multi-hop. When ≥1 hop resolves the line,
  return a new `status: "renamed_chain"` with `chain: [{commit, from, to, commitMessage}]`, `finalLine`,
  `finalContent`, and `confidence` (`high` for ≤3 hops, else `medium`).
- **Why same-position replacement (not any `modified`):** it is the precise rename signal from the ticket, so
  ordinary content edits are never mislabeled as renames, and pure deletions (no replacement) keep returning the
  existing `deleted` result untouched.

Chose Approach A (server-side follow-through) over B (broaden core's `traceLineThroughHunks` — cross-repo, wider
blast radius, and doesn't itself emit the chain) and C (agent-guide only — fragile). The skill-guide note (C) is
folded in. Uses only existing `@agentic-bookmarks/core` exports → **single-repo change, no core edits**. Breaking
risk LOW: the trace result is agent-facing JSON (no programmatic consumers). `tools/anchor-git.ts` gains a
`toWire()` for the new 0-based `finalLine`; the `anchor_traceLineHistory` definition documents `renamed_chain`.
New `trace-line-history.test.ts` cases cover grouped 1-hop and 2-hop renames, rename-then-deletion, and a
pure-deletion regression guard.
