# SML-1507: Data-file watcher omits onDidCreate → stale tree after git re-creates a shared data file (incomplete SML-1502)

The data-file watcher in `watchers.ts` (L139-140) wires only `onDidChange` + `onDidDelete`; the pulse
watcher just above it wires all three (change/create/delete). When git **re-creates** an absent committed
`shared/*.json` (branch switch / `stash pop` / `pull` into a branch where the file exists), only
`onDidCreate` fires — and it's unhandled, so the extension neither invalidates its read cache nor schedules
a tree/decoration refresh. The pulse watcher can't compensate: the pulse lives under the gitignored
`.bookmarks/local/`, which git never touches. SML-1502's `dataMtime` gating means the read cache
self-corrects on the next read, so the bug is a missing *scheduled refresh*, not permanently wrong data.

- **Fix (from the ticket):** wire the existing `onDataFileChanged` handler onto the data watcher's
  `onDidCreate` too — `dataWatcher.onDidCreate(onDataFileChanged);` — placed between the existing
  `onDidChange` and `onDidDelete` registrations to mirror the canonical change→create→delete ordering
  used by the pulse / registry / mcp2ext watchers. The handler is already idempotent (invalidate cache +
  fire-and-forget debounced `refresh`), so this is purely additive: no signature change, no new watcher,
  no consumer impact (`extension.ts` is the only consumer).
- **Why this is safe:** the create+change double-fire for a single git op is already collapsed by the
  shared debounce + 300ms sticky-suppress guard (proven by the existing "no flicker" test); and onDidCreate
  attaches to the *same* `dataWatcher`, so the SML-1504 restart watcher-count (2 per file) is unchanged.
- **Tests:** add one regression test mirroring the SML-1502 `onDidChange` test — fire
  `createdWatchers[1].onDidCreate[0]`, assert `invalidateFileCache` runs once synchronously and
  `revalidateAndRepaint` is scheduled once after the 100ms debounce. The vscode mock already captures
  `onDidCreate`, so no mock change is needed. Closes the previously-untested onDidCreate gap.

**Scope:** small (2 files; 1 additive source line + 1 test case)
