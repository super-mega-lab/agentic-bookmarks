# SML-1467 — Anchor repair: detect signature refactoring via body continuity

## Problem
When a function's signature is refactored in place (params→options object, generics added/removed, async conversion, return-type/visibility change) but the function stays at ~the same location with a continuous body, the bookmark's `lineCache` (old declaration line) no longer matches, so `diagnoseDiff` returns `no_match` and the repair waterfall declares the bookmark non-repairable.

## Approach
Add a new `signature_changed` tier to core's pure `diagnoseDiff` (`agentic-bookmarks-core/src/anchor-repair.ts`), inserted only at the post-fuzzy `no_match` site so existing tiers are untouched. A new exported `detectSignatureChange(anchor, currentFileLines)`:
1. Extracts the function/method name from the declaration `lineCache` (`extractDeclarationName` — handles visibility/`function`/`async`/`get`/`set`/generics; rejects calls and control-flow).
2. Finds a same-named declaration with a different signature in the current file.
3. Scores **body continuity** (old `anchor.contextAfter` vs the candidate's following lines via `tokenFuzzyScore`) — the primary signal, since raw line-delta is unreliable under shift.

Confidence: `bodySim ≥ 0.5` → high; `0.3–0.5` → medium; uncomputable but candidate within ±6 lines → medium; otherwise `null` (fall through to the existing informative `no_match`). Low-confidence is intentionally not surfaced.

Result detail: `{ functionName, oldSignature, newSignature, newLine (0-based), confidence, bodySimilarity, explanation }`. The server's existing `convertFileDiffLinesToWire` already converts `detail.newLine` 0→1-based, so no server logic change is needed for correctness.

## Changes
- **Core (separate PR):** `src/anchor-repair.ts` (new `SignatureChangedDetail`, union member, `detectSignatureChange` + `extractDeclarationName`, wired at the no_match site) + `src/anchor-repair.test.ts` (unit + integration tests via synthetic `FileDiff`).
- **Extension (this repo):** doc-only — `packages/server/src/tools/definitions.ts` (add `signature_changed` to the `anchor_getFileDiff` description) and `packages/server/src/anchor-git-tools.ts` (one Step-3 bullet in the repair skill guide).

## Out of scope (ticket Limitations)
Fuzzy/low-confidence *name* matching, function-renamed-in-same-commit, full rewrites, and class-declaration matching.
