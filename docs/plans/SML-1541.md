# SML-1541: Scan auto-repair idle-wait can exit before repairs are enqueued (F-030)

Scan-All Phase 2 triggers repair then polls `!isRepairIdle()` as the loop *entry* condition with no settle.
Enqueue is deferred behind the `onDidOpenTextDocument → openAndRepaint → enqueue` chain, so the wait can
exit before any repair registers → Phase 3 reconciles the pre-repair (broken) state into the authoritative
cache. Separately, `openTextDocument` doesn't re-fire the open event for already-open docs, so those targets
were never enqueued at all.

Two-part fix:
- **`scanQueue.ts`** — drain-wait loop now delays one tick (settle) *before* checking `isRepairIdle()`
  (do-while shape) instead of checking idle first. A just-registered enqueue is no longer skipped. Still
  bounded by `MAX_IDLE_POLLS`.
- **`extension.ts`** `triggerRepair` — after `openTextDocument`, `await openAndRepaint(doc)`, which resolves
  anchors (populates broken state) and enqueues the doc directly for BOTH fresh and already-open docs, rather
  than relying on the deferred open event.
