# SML-1542 [F-031]: Rank midpoint exhaustion collides instead of rebalancing on repeated reorders into the same gap

Drag/drop reorder assigns a sparse-integer rank via `assignRankBetween(prev,next) = floor((prev+next)/2)`. Repeated drops into one gap halve it each time (150,125,…,101) until `floor((100+101)/2)=100 == prev` — a collision after ~7 drops, so the dragged item visibly fails to land where dropped and the slot freezes. `ensureRanksAround` can't help: it short-circuits when neighbors are already ranked (`unrankedCount <= 0`), which is exactly the all-ranked DnD reorder case. Collisions persist to `ordering.json` and survive reloads. Separately, `applySort` user-mode sorts ranked items by rank only, so any equal ranks order ambiguously (by input order).

**Approach — own the guard in `rank.ts`, not the controller.** Add a pure `rankForInsert(siblings, insertIdx, getRank, setRank)` that routes through `ensureRanksAround`, computes `assignRankBetween(prev,next)`, and — if the result collides (`rank <= prev || rank >= next`) — `rebalance`s the sibling list (restoring `RANK_STEP` gaps) and recomputes. One rebalance is provably sufficient (guarantees gaps of 100). This keeps `assignRankBetween` pure and makes the exhaustion path unit-testable with the simple `Sib` shape — preferred over an inline branch in the vscode-coupled controller. It mirrors how `ensureRanksAround` already owns the "no room → rebalance whole list" decision.

**Fix.**
- `rank.ts`: add `rankForInsert` (ensure → assign → collision-guard → rebalance → recompute).
- `dnd-controller.ts`: replace the `ensureRanksAround` + `assignRankBetween` block (lines 102-105) with a single `rankForInsert(...)` call; swap the now-unused imports for `rankForInsert`.
- `applySort.ts`: add a stable secondary tiebreaker to user-mode — `(get(a)-get(b)) || defaultCmp(a,b)`. This is the only change that helps **already-persisted** duplicate ranks (the controller fix only prevents new ones).

**Files:** `packages/extension/src/ordering/rank.ts`, `dnd-controller.ts`, `applySort.ts`, plus `rank.test.ts` (rankForInsert: room / gap-exhausted-rebalance / append) and `applySort.test.ts` (rank-tie → defaultCmp).
**Scope:** small. No core / DB / env / dependency changes. Baseline 872/872 tests + typecheck + lint stay green.
