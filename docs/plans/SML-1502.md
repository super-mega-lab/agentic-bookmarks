# SML-1502: External/git writes to bookmark data files are invisible

External writers (`git checkout`/`pull`/`stash`/`rebase`, manual edits) rewrite committed
`.bookmarks/shared/*.json` but never bump the gitignored `.pulse`. Both pulse-gated caches keep
serving the previous branch's data: the extension UI doesn't refresh, and the watcher-less MCP
server's `fileCache` returns stale parses. Two complementary self-corrections, one per process.

- **Extension fix (`watchers.ts`):** the data-file watcher only wired `onDidDelete`. Register the
  same invalidate-cache + debounced-`refresh` handler on `onDidChange`, so git-driven modifies route
  through the existing `revalidateAndRepaint`. The shared 100ms debounce + `STICKY_PULSE_SUPPRESS_MS`
  guard already collapse our own write's pulse+data double-fire into one repaint (no flicker).
- **Core fix (`store_v2.ts` `readFileV2`):** the read cache was gated only on the `.pulse` mtime,
  which external writers never move. Add `getDataMtime` (mirrors `getPulseMtime`), extend the cache
  entry with `dataMtime?`, and require BOTH pulse and data mtime to match on a cache hit. Populate
  `dataMtime` at all three `fileCache.set` sites; capture it BEFORE the content read in `readFileV2`
  so the read→cache window self-corrects. This is what lets the watcher-less MCP process return fresh
  data on its next read (the MCP acceptance criterion).
- **Tests:** core — an external data-file write that doesn't bump the pulse is now seen on the next
  `readFileV2` (and an `editFileV2` write stays a cache hit); extension — data-file `onDidChange`
  invalidates the cache synchronously and schedules one debounced refresh (mirrors the `onDidDelete` test).
