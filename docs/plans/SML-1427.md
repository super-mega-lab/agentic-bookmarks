# Implementation Plan — SML-1427: MCP install to also do .gitignore setup

## Overview
When a user completes any MCP setup flow (Claude Code, Cursor, Codex), automatically apply the `.gitignore` change as part of the same flow. This eliminates the need to notice and act on a separate pop-up. The standalone gitignore nudge is suppressed after MCP setup applies the change.

## Files to Modify
1. `packages/extension/src/commands/mcp-setup-helpers.ts` — add `applyGitignoreSetup` helper
2. `packages/extension/src/commands/mcp-setup-helpers.test.ts` — tests for `applyGitignoreSetup`
3. `packages/extension/src/commands/mcp-config-and-diagnostics.ts` — call gitignore setup in each `apply*Setup()`; add `refreshWelcomeView?` to deps
4. `packages/extension/src/extension.ts` — pass `refreshWelcomeView: () => welcomeProvider.refresh()` in deps

## Approach
Extract a testable `applyGitignoreSetup(deps)` helper (following the `mcp-setup-helpers.ts` pattern) that:
1. Calls `appendGitignoreLine(workspaceRoot, BOOKMARKS_LOCAL_GITIGNORE_LINE)`
2. Marks `GITIGNORE_NUDGE_SHOWN_KEY = true` in workspaceState (suppresses standalone nudge)
3. Logs outcome (info or error)
4. Never throws — errors are caught and logged

Wire this into each `apply*Setup()` function in `mcp-config-and-diagnostics.ts` after the primary setup action. Then call `deps.refreshWelcomeView?.()` to clear the welcome-page banner if present.

## Shared Interfaces

### `ApplyGitignoreSetupDeps` (in mcp-setup-helpers.ts)
```typescript
import { GITIGNORE_NUDGE_SHOWN_KEY, type WorkspaceStateLike } from '../gitignore-nudge';
import { appendGitignoreLine, BOOKMARKS_LOCAL_GITIGNORE_LINE } from '@agentic-bookmarks/core';

export interface ApplyGitignoreSetupDeps {
  workspaceRoot: string;
  workspaceState: WorkspaceStateLike;
  log: { error(msg: string): void; info(msg: string): void };
  appendGitignoreLineFn?: typeof appendGitignoreLine;
}

export async function applyGitignoreSetup(deps: ApplyGitignoreSetupDeps): Promise<void>
```

### Change to `McpConfigAndDiagnosticsDeps`
```typescript
refreshWelcomeView?: () => void;  // optional, called after gitignore applied
```

## Implementation Units

### Unit 1 — `applyGitignoreSetup` helper + tests (depends on: none)
**Source**: `packages/extension/src/commands/mcp-setup-helpers.ts`
**Test**: `packages/extension/src/commands/mcp-setup-helpers.test.ts`

Steps:
1. Write failing test cases first (TDD)
2. Add imports: `GITIGNORE_NUDGE_SHOWN_KEY` from `../gitignore-nudge`; `appendGitignoreLine`, `BOOKMARKS_LOCAL_GITIGNORE_LINE` from `@agentic-bookmarks/core`
3. Add `ApplyGitignoreSetupDeps` interface and `applyGitignoreSetup` function

Test cases:
- Calls `appendGitignoreLine` with correct args
- Marks `GITIGNORE_NUDGE_SHOWN_KEY = true` in workspaceState on success
- Marks nudge shown even when status is `already-present`
- Logs the status info
- On error: catches exception, logs it, does NOT mark nudge shown (since gitignore wasn't actually updated)
- Never throws

### Unit 2 — Wire into commands + extension (depends on: Unit 1)
**Source**: `packages/extension/src/commands/mcp-config-and-diagnostics.ts`, `packages/extension/src/extension.ts`
**Test**: none (VS Code API dependent; behavior verified by typecheck + existing integration)

Steps:
1. Add `refreshWelcomeView?: () => void` to `McpConfigAndDiagnosticsDeps`
2. Import `applyGitignoreSetup` from `./mcp-setup-helpers`
3. In each `apply*Setup()` function, after the primary setup action, add:
   ```typescript
   await applyGitignoreSetup({ workspaceRoot, workspaceState: context.workspaceState, log });
   deps.refreshWelcomeView?.();
   ```
   (Wrap in try/catch only if needed — `applyGitignoreSetup` never throws)
4. In `extension.ts`, add `refreshWelcomeView: () => welcomeProvider.refresh()` to the deps object

## Edge Cases
- `.gitignore` already has the line: `appendGitignoreLine` returns `'already-present'` — idempotent, nudge key still marked
- `workspaceRoot` is empty or workspace not open: `applyClaudeSetup` is only called after scope is selected from quick-pick, which requires a workspace; but guard defensively
- Error writing `.gitignore` (permissions): catch, log, do not surface to user (MCP setup itself succeeded)
- `refreshWelcomeView` not provided: optional field, `?.()` handles it

## Acceptance Criteria Mapping
- AC1: Each MCP setup button calls `applyGitignoreSetup` → Unit 1 + Unit 2
- AC2: `appendGitignoreLine` is idempotent by design → Unit 1 (test for `already-present`)
- AC3: Mark `GITIGNORE_NUDGE_SHOWN_KEY = true` after MCP setup → Unit 1 + Unit 2

## Risk Assessment
- Low risk: only adding to existing functions, not removing anything
- `refreshWelcomeView` is optional so wiring is non-breaking
- Error handling ensures MCP setup still succeeds even if gitignore step fails
