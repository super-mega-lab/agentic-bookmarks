# SML-1495 — Harden revalidateOpenDocuments against a single failing document

Scope: **small** (extension-only, 2 files). Branch: `SML-1495/harden-revalidate-open-documents`. Surfaced by the SML-1491 code review (PR #31), finding #2. Related: SML-1496 (centralize the revalidate→decorate ordering invariant).

## Problem
`revalidateOpenDocuments()` in `packages/extension/src/anchor-resolution.ts` (~lines 180–186) awaits `onFileOpened(document)` per open document with no per-document try/catch. If `onFileOpened` throws for one doc (e.g. `getText()` on a disposing document, or `getAllBookmarksForUri` rejects), the `for` loop aborts and every *remaining* open document keeps stale anchor state. Post-SML-1491 the pulse caller wraps the whole call in try/catch (so the repaint still runs), but that outer guard can't recover the documents the aborted inner loop skipped.

## Fix
Wrap only the `await onFileOpened(document)` inside the loop in try/catch; on error `log.error(\`[anchorState] revalidate failed for <uri>: ${err?.message || err}\`)` and `continue`. No signature change — all three callers (`extension.ts`, `watchers.ts` pulse path, `commands/mcp-config-and-diagnostics.ts`) are unaffected. Mirrors the existing in-file `[contextRefresh]` catch and the sibling `[pulse]` guard in `watchers.ts`. This is the *inner* guard complementing the SML-1491 *outer* guard.
