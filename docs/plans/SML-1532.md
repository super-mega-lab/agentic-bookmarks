# Implementation Plan: SML-1532

## Ticket
**[F-021] `activateForWorkspace` has no top-level error handling and marks itself done before awaiting**

`hasScoped = true` is set BEFORE `await activateForWorkspace(...)`, whose body has no enclosing try/catch. If any awaited step rejects (`OrderingService.load`, `bootstrapWorkspaces`, `readRegistry` on corrupt-registry+failed-backup, `watchers.setupWatchers`, `repaintAfter`), the `void maybeActivateForWorkspace()` rejection goes unhandled and — because `hasScoped` is already true — no later folder change retries. The extension is left permanently half-initialized (trees/watchers/decorations/commands/MCP missing) with no surfaced error, recoverable only by a window reload.

## Scope Classification
Small — 3 files, extension repo only (1 modified source, 1 new source, 1 new test). No core, DB, or config changes.

## Overview
Make the deferred scoped-activation trigger catch and surface failures, commit its "done" flag only after `activateForWorkspace` resolves (so later folder changes retry), and keep a synchronous re-entry guard while a run is in flight.

## Approach Decision
Extract the run-once/retry/in-flight logic into a small `create*` factory, `createScopedActivationGuard`, so it is unit-testable without `extension.ts`'s ~60-import, vscode-dependent surface — matching the codebase's factory + isolated-test convention (watchers, decorations, revalidate-and-repaint). `extension.ts` keeps the inline `workspaceFolders` check and delegates run-once/retry/error handling to the guard. Rejected the inline try/catch alternative because `extension.ts` can't be imported in a test, leaving the exact regression unverifiable.

## Files to Modify
- `packages/extension/src/extension.ts` — import `createScopedActivationGuard`; replace the `hasScoped`-before-await closure (~lines 171-181) with a guard whose `run` calls `activateForWorkspace` and whose `onError` logs + shows a `vscode.window.showErrorMessage`; keep the inline folder check and the listener/`await` call shape.

## New Files
- `packages/extension/src/scoped-activation-guard.ts` — `createScopedActivationGuard({ run, onError })`: runs at most once on success, guards re-entry while in flight, resets on failure, reports via `onError`, never rejects.
- `packages/extension/src/scoped-activation-guard.test.ts` — guard-contract unit tests (no vscode mock needed).

## Implementation Units

### Unit 1: scoped activation guard + wiring (no deps)
- New factory + wire `maybeActivateForWorkspace` to use it.
- Tests:
  - rejection ⇒ `onError` called, trigger does not reject (AC1)
  - failed run ⇒ retries on next trigger, then no-op once it succeeds (AC2)
  - re-entry while in flight ⇒ no second concurrent run (AC3)
  - success ⇒ runs at most once (AC4)

## Invariants to Preserve
Workspace-agnostic activation unchanged; scoped phase still runs at most once on success; `onDidChangeWorkspaceFolders` retry-when-folder-appears preserved (and now also retries after a *failed* run).

## Risk
Very low — additive new file + a localized closure rewrite at the activation entry point (no in-repo importers); no success-path behavior change; covered by new unit tests; full extension suite (baseline 675/675) and typecheck must stay green.
