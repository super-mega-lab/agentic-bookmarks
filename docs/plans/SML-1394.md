# SML-1394 — Defer workspace-scoped activation until a folder is opened

**Status:** Design agreed, ready to plan
**Date:** 2026-05-20

## Problem

When VS Code launches with no folder open, `activate()` derives
`workspaceRoot` from `process.cwd()` (typically `/` on macOS) at
`packages/extension/src/extension.ts:82`. That bogus root is then threaded
through `bootstrapWorkspaces` (which tries to `mkdir /.bookmarks` and logs an
`ENOENT`) and through every provider, watcher, and service constructed during
activation. Even after the user opens a folder, the extension stays half-wired
against `/` until the window is reloaded.

## Approach: split activation into two phases

### Agnostic phase — runs unconditionally at `activate()`

- Output channel + logger + `logLevel` config listener.
- `WelcomeViewProvider` registration (only needs `extensionUri`; see below).
- A **scope watchdog**: a single `onDidChangeWorkspaceFolders` subscription
  that calls `activateForWorkspace()` exactly once when folders first go from
  empty to non-empty. Guarded by a `hasScoped` flag.
- Eager call to `activateForWorkspace()` if `workspaceFolders?.length` is
  already truthy at activation.
- Does not touch the filesystem under any workspace root and does not capture
  a `workspaceRoot`.

### Scoped phase — `activateForWorkspace(context, log, outputChannel)`, runs at most once

Top-of-function guard: if `!workspaceFolders?.length`, log an error and return
(makes the old `/` path unreachable).

Everything that currently lives at `extension.ts:82` onward moves here:

- `workspaceRoot = workspaceFolders[0].uri.fsPath`, `defaultDataRoot`,
  `defaultLocalPath`, `paths`.
- `migrateLocalLayout` per folder; `maybeShowGitignoreNudge` per folder.
- `bootstrapWorkspaces`.
- Providers (Bookmarks, FilesGroups, Settings) + tree views.
- Licensing service + its listeners.
- Status bar + listeners; ordering service.
- Decoration manager, watchers, sticky, repair queue.
- Anchor resolution, CodeLens.
- Document / save / rename / active-editor listeners.
- All `registerXCommands(...)` calls.
- MCP server registration + the MCP "needs update" prompt.
- `agenticBookmarks.dataRoot` config listener.

### Commands when no folder is open

Decision: **commands are registered only in the scoped phase.** With no folder
open, the `agenticBookmarks.*` commands are not registered; VS Code shows its
standard "command not found" if one is triggered externally. No stubs. This is
the smallest, lowest-risk change and matches reality (nothing to bookmark).

### `process.cwd()` removal

Removed at both sites:
- `extension.ts:82` — replaced by the scoped-phase derivation + guard.
- `extension.ts:724` (inside `provideMcpServerDefinitions`) — that callback only
  runs after the scoped phase registered it, so it reads `workspaceFolders[0]`
  directly.

## Welcome view becomes folder-aware

`WelcomeViewProvider` gains two render modes, branching on
`workspaceFolders?.length`:

**Empty mode (no folder):** intentionally minimal so it's obvious the extension
is inactive and nothing competes for attention:
- Hero (title + icon + tagline) — kept.
- One CTA: "Open a folder to activate Agentic Bookmarks." + an "Open Folder…"
  button (`command:vscode.openFolder`).
- No Learn cards, no MCP setup buttons.

**Active mode (folder loaded):** current full content (Learn cards, MCP setup).
This is where future folder-specific UI will live (e.g. per-agent MCP install
state) — out of scope for this ticket but the motivation for making the view
folder-aware now.

**Refresh wiring:** the provider subscribes to `onDidChangeWorkspaceFolders`
itself (constructor takes `context.subscriptions` to track the disposable),
holds the resolved `WebviewView`, and re-renders `webview.html` on change.
Provider-internal subscription keeps the view self-contained and decoupled
from the activation-phase plumbing.

## Out of scope (see follow-up doc)

Multi-root churn after the first activation — primary folder (`workspaceFolders[0]`)
removed or swapped while still non-empty, and teardown on drop-to-zero — is
**not** handled here. The scoped phase runs once and never tears down; this
matches current behavior for those transitions. Documented separately in
`docs/plans/2026-05-20-multi-root-primary-rebind.md`.

## Acceptance criteria mapping

1. Empty launch → no ENOENT, no writes under `/`: scoped phase (incl.
   `bootstrapWorkspaces`, migration, nudge) never runs while empty. ✓
2. Open folder in same window → full activation without reload: watchdog fires
   `activateForWorkspace()` on the 0→1+ transition. ✓
3. Launch directly on a folder → identical to today: eager call when
   `workspaceFolders` already populated; same code, same order. ✓
4. `process.cwd()` fallback removed/unreachable: deleted at both sites, replaced
   by the guard. ✓

## Testing

- `WelcomeViewProvider.getHtml()` empty-vs-active branch is pure → unit test.
- Full activation needs a VS Code host; verified manually in the Extension
  Development Host:
  - Launch with no folder → no ENOENT in the output channel, welcome view shows
    the Open Folder CTA.
  - Open a folder in that window → tree views populate, commands work, no reload.
  - Launch directly on a folder → behaves as today.
