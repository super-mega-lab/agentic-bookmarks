# SML-1520: Fix cross-file changeGroup data loss on destination write failure

The cross-file branch of `agenticBookmarks.changeGroup` removed the bookmark from the source file (committed) before writing the destination. If the destination write threw, the bookmark was lost from both files (silent data loss, handled only by a toast).

**Fix:** reorder to destination-first. Extract the move into a vscode-free, dependency-injected helper `moveBookmarkAcrossFiles` that reads the source read-only, writes the bookmark to the destination first, then removes it from the source only after that write resolves. A failed destination write now leaves the source intact. The worst residual failure (source removal throwing after the destination commit) is a recoverable duplicate, not data loss.

The ticket's `moveGroupBetweenFiles` suggestion was evaluated and not used — that core primitive moves whole groups, not a single bookmark.

**Files:** `packages/extension/src/commands/group-management-helpers.ts` (new), `group-management-helpers.test.ts` (new, 3 DI tests incl. the dest-failure regression), `group-management.ts` (cross-file branch routed through the helper).
**Scope:** small (3 files; same-file branch unchanged).
