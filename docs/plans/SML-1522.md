# Implementation Plan: SML-1522

## Ticket
**[F-011] `group_moveFile` emits 0-based tag line numbers while every other MCP tool emits 1-based**

`handleGroupMoveFile` forwards core's `moveResult.tagInsertions`/`tagRemovals` straight into the wire JSON with no `toWire()`. Core populates those `line` fields from `resolveAnchors()` (0-based), but the MCP wire convention is 1-based — every other tag-emitting tool converts (`bookmark_add`, `bookmark_delete`, `anchor_repair`). An agent following the returned values edits the `@bookmark` tag comment one line too high, corrupting source files or orphaning/duplicating tags. Only triggers when the destination file resolves to tag anchors.

## Scope Classification
Small — 2 files in the extension repo (1 source, 1 test). No core changes.

## Overview
Map the `line` field of both `tagInsertions` and `tagRemovals` through `toWire()` in `handleGroupMoveFile` before serialization, mirroring the three sibling tools. The in-process extension consumer (`group-management.ts`) reads the same core values as 0-based and is untouched, so the fix belongs at the MCP wire boundary, not in core.

## Approach Decision
Map inline in the return object (`.map(t => ({ ...t, line: toWire(t.line) }))`), exactly mirroring `bookmark_add` (`bookmark.ts:307`), `anchor_repair` (`anchor-repair.ts:492,497`), and `bookmark_delete` (`bookmark.ts:423`). No new helper (siblings don't use one); core stays 0-based by contract.

## Files to Modify
- `packages/server/src/tools/file-group.ts` — add `import { toWire } from './line-basis.js';`; map `tagInsertions`/`tagRemovals` `line` fields in the `handleGroupMoveFile` return.
- `packages/server/src/tools/file-group.test.ts` — add 2 regression tests (tag-insertion and tag-removal 1-based emission) using real core ops against temp dirs.

## New Files
None.

## Implementation Units

### Unit 1: 1-based tag-edit wire conversion (no deps)
- Convert `moveResult.tagInsertions` / `moveResult.tagRemovals` `line` → `toWire(line)` in the returned JSON.
- Tests:
  - Point-anchored group → `defaultAnchorType:'tag'` dest ⇒ `tagInsertions[0].line` is 1-based (core 0-based line 2 ⇒ wire 3).
  - Tag-anchored group → `defaultAnchorType:'smart'` dest ⇒ `tagRemovals[0].line` is 1-based (marker line + 1).

## Risk
Very low — two-line additive change on the wire boundary, covered by new tests, mirrors three existing tools, no consumer contract change (consumers already expect 1-based).
