# SML-1537 [F-026]: Toggle/remove match smart and tag anchors against stored `lastUpdatedLine`, not the live resolved line

`findBookmarksOnLineMatching` (used by `runToggle` and reveal-in-panel) and the `removeAtLine` inline filter compare the requested line against `anchor.lastUpdatedLine` for smart/tag anchors. But every display path — decorations, CodeLens, jump, quickpicks, export — renders those anchors at the **live** line via `getResolvedLine`/`liveLineFor`/`makeResolveLine`. `applyEditDelta` shifts the in-memory resolved line per edit without persisting `lastUpdatedLine`, so after an edit the match line and the visible line diverge: toggling/removing on the line the user actually sees misses the bookmark (and re-adds a duplicate), while the stale line could remove the wrong one. Point/range anchors are unaffected (they store the literal line). Transient and non-destructive — it self-corrects on the next revalidation writeback — but user-visible as "toggle did nothing" / "remove removed the wrong one."

**Approach — mirror `liveLineFor`, inject the resolver.** Compute an *effective line* = `getResolvedLine() ?? lastUpdatedLine` for smart/tag at the three match sites. The matcher is a documented *pure* helper, so rather than importing `getResolvedLine` into it (Approach B — couples it to vscode/global state, kills its testability) or threading the private `liveLineFor` out of `bookmark-jump-helpers.ts` (Approach C — needless cross-file coupling), the resolver is injected as an optional `resolveLine?: (bookmarkId) => number | undefined` callback — the same dependency-injection idiom as `makeResolveLine`. A small exported `effectiveAnchorLine(anchor, resolveLive)` centralizes the point/range/smart/tag line logic so the three sites can't drift apart again. Backward compatible: with no resolver, smart/tag fall back to `lastUpdatedLine`, so existing behavior and all 16 helper tests are unchanged.

**Fix.**
- `find-bookmarks-on-line.ts`: add `resolveLine?` to `FindOptions`; add `effectiveAnchorLine`; tag/smart branches match on the effective line; tag matches surface `tagLine = effective (live) line`.
- `bookmark-crud.ts`: `runToggle` passes `resolveLine: id => getResolvedLine(editor.document.uri.toString(), id)`; the `removeAtLine` filter uses `effectiveAnchorLine` for smart/tag and pushes the **live** line into `tagAnchorsToRemove`. This second part also fixes a latent defect: `removeTagComment` edits `document.lineAt(line)` exactly, so the stale `lastUpdatedLine` previously failed to strip a comment the edits had moved.
- `reveal-in-panel.ts`: passes the same resolver (the helper's other caller has the identical bug; one-line fix keeps callers consistent).

**Files:** `packages/extension/src/commands/find-bookmarks-on-line.ts`, `bookmark-crud.ts`, `reveal-in-panel.ts`, `find-bookmarks-on-line.test.ts` (new `effectiveAnchorLine` cases + smart/tag live-line + fallback cases).
**Scope:** small. No core / DB / env / dependency changes. Baseline 847/847 tests + typecheck + lint stay green.
