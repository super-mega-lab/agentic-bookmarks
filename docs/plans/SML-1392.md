# SML-1392: bookmark_add ignores registered shared files when auto-creating groups

When `bookmark_add` is given a `groupName` that doesn't exist yet, the new group is unconditionally
created in the workspace's **local** file via `getOrCreateLocalFile()` (`bookmark.ts:142-155`). There is
no way to direct the new group into an already-registered **shared** file: an agent that does
`file_register → bookmark_add(groupName)` silently lands everything in `.bookmarks/local/bookmarks.json`
while the registered shared file stays empty. The response returns `fileId` but not the destination
path, so the caller can't even detect the wrong-file routing.

- **Fix (Option 1 from the ticket):** add an optional `filePath`/`fileId` destination hint to
  `bookmark_add`, mirroring `group_create`.
  - `bookmark.ts`: destructure `fileId`/`filePath`; in the new-group branch, resolve an explicit hint to
    a **registered, enabled** file in the same workspace (fileId → registry lookup; filePath →
    `resolveWorkspacePath` matched against registry entries) and create the group there before the
    `getOrCreateLocalFile` fallback. An explicit-but-unresolvable hint returns `success:false` (loud
    failure) rather than silently routing to local — silent routing is the bug. Add `filePath`
    (workspace-relative) to **both** success responses (tag + non-tag) so callers can verify the
    destination.
  - `definitions.ts`: add `fileId`/`filePath` to the `bookmark_add` input schema + a one-line
    description note. Additive/optional → backward compatible (omitting the hint preserves today's
    local-file behavior).
- **Why not Option 2 (sticky default target on file_register):** introduces silent, order-dependent
  global routing ("most-recently-registered wins") — the same implicit behavior that caused the bug. The
  ticket itself flags it as riskier.
- **Out of scope (separate tickets):** the two "Related symptom" sections — stale VS Code "Files +
  Groups" panel after `group_moveFile` (extension watcher reconciliation; overlaps SML-1494 + the
  cache-coherence root cause) and `file_deregister --force` to drop orphan nameIndex entries. Distinct
  subsystems; bundling would balloon a small server fix.
- **Tests:** new `bookmark.test.ts` (no handler tests exist today) modeled on `file-group.test.ts` —
  new group routes into the registered file via `filePath` and via `fileId`; unresolvable hint errors and
  writes nothing to local; no-hint regression still lands in local; existing group ignores the hint.
