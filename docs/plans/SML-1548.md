# SML-1548: F-037 — bookmarks://files aborts entirely if one workspace registry is corrupted

`handleReadResource('bookmarks://files')` loops `ctx.workspaces` and calls `getRegistryForWorkspace(ws)`
(a core `readRegistry` wrapper) **outside** any try/catch. Core `readRegistry` throws when the registry is
corrupted and `.bak` recovery also fails, so the uncaught throw aborts the whole loop and fails the resource
for **every** workspace — not just the bad one. (The inner per-file `readFileAt` was already guarded.)

**Fix:** wrap the per-workspace body (registry read + file loop) in a `try/catch`; on failure `console.error`
(stdout is the JSON-RPC channel) and `continue`, so one bad registry degrades to the readable workspaces
instead of failing entirely.

**Tests:** add a `bookmarks://files` block to `resource-handlers.test.ts` (previously uncovered) — mock
`getRegistryForWorkspace` to throw for one workspace; assert (1) a healthy second workspace's files still
return, and (2) a lone corrupted workspace yields `{ files: [] }` rather than throwing.

**Files:** `packages/server/src/resource-handlers.ts`, `packages/server/src/resource-handlers.test.ts`
**Scope:** small (1 source + 1 test, behavior-preserving except the degraded-vs-abort outcome)
**Branch:** `SML-1548/guard-corrupt-registry-read`
