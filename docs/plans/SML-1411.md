# SML-1411 — Implementation Plan

**Title:** Extract `composedIsFileHidden` visibility predicate to a shared, tested helper
**Scope:** small (1 helper added + 1 new test file + 4 call-site replacements across 3 files — 5 files total)
**Branch:** SML-1411/extract-compose-file-hidden-predicate
**Design decision (Phase 2):** Single implementation unit — extract `composeFileHiddenPredicate` into `bookmark-loaders.ts`, write a dedicated `bookmark-loaders.test.ts` covering all branches, then mechanically replace the four verbatim copies. The strictest typing (from `bookmark-bulk-open.ts:98-107`) is the reference; all four call sites converge on the new helper's narrow casts.

## Overview

Today the `composedIsFileHidden` closure — which encodes SML-1380's "Bullseye trumps file-level UI-hide; registry-disable still wins" precedence — is copy-pasted verbatim in four command bodies (`listInFile`, `listAll`, `export`, `collectTargets` in bulk-open). A fifth/sixth caller will copy it again, and the SML-1380 comment will eventually drift in one site and not another.

The fix: lift the closure into `composeFileHiddenPredicate(folders, filesData, visibility, isFileHidden): (fileId) => boolean` in `bookmark-loaders.ts` (natural home — `LoadedFolder`/`LoadedFile` already live there), write a dedicated test file that exercises every branch with real fixtures (no mocking — the existing tests mock the predicate, which is the coverage gap the ticket is fixing), and replace all four call sites.

Pure refactor: zero behavioral change. The new helper's six tests cover:
1. fileId not in any loaded folder → false
2. `isFileHidden(fileId, reg) === false` → false
3. `reg.files[..].enabled === false` (Bullseye off) → true
4. Registry-disabled even in Bullseye mode → true (registry wins)
5. Bullseye on + UI-hidden + enabled → false (bullseye wins)
6. Bullseye off + UI-hidden + enabled → true
