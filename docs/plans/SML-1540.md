# SML-1540: Per-workspace-folder file/registry watchers in multi-root workspaces

`createWatcherManager` was instantiated once with `workspaceFolders[0]`, so `setupWatchers` (per-file
pulse+data), `setupRegistryWatcher`, and `setupMcpToExtensionWatcher` watched only the primary folder. The
`onDidChangeWorkspaceFolders` handlers never (re)bound watchers. External writes (git checkout/pull/stash,
manual edits, MCP `file_create`/`file_register`) to a SECONDARY folder's shared data file or registry didn't
invalidate the read cache or refresh the UI, and folders added after activation were never watched — stale
panel until a window reload.

- **(a)** Add a unified, idempotent `dispose()` to the watcher manager (tears down its file + registry + mcp
  watchers) and stop self-registering into `context.subscriptions`; track the registry/mcp watchers in a
  manager-owned `ownDisposables` array. Drop the now-unused `context` field from `WatcherDeps`.
- **(b)** Add `createWatcherManagerSet({ getRoots, makeDeps, getLastStickyRefreshAt })` — owns a
  `Map<root, manager>`, exposes a serialized `sync()` that creates a manager per workspace folder and disposes
  managers for removed folders, plus `dispose()` for teardown. This is the `Map<root, manager>` from the
  finding, factored out so the add/remove/dispose logic is unit-testable.
- **(c)** In `extension.ts`, replace the single primary-only watcher + mcp-consumer wiring with a per-folder
  `makeWatcherDeps(root)` (each folder gets its own `QueueConsumer`, truncated on setup), call
  `watcherSet.sync()` on activation, register `watcherSet.dispose()` in `context.subscriptions`, and re-`sync()`
  on `onDidChangeWorkspaceFolders` (add new folders, dispose removed ones). Shared UI-refresh callbacks (already
  workspace-wide) stay global.

`activateForWorkspace` still binds providers to the primary folder — primary-folder *removal* leaving providers
stale is a separate concern, out of scope here. Preserves SML-1504 (deactivate teardown / no double-watch),
SML-1502/1507 (data-file change/create/delete cache invalidation). Covered by new `watchers.test.ts` tests for
`dispose()` and the per-folder set's add/remove/dispose-all.
