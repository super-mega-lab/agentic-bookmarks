# SML-1497 — Avoid redundant tree refreshes on each bookmark pulse

Scope: **small** (extension-only, 2 files). Branch: `SML-1497/avoid-redundant-tree-refreshes`. Surfaced by the SML-1491 code review (PR #31), finding #5 (efficiency). Related: SML-1495, SML-1498, SML-1491.

## Problem
On each bookmark data-file pulse, `watchers.ts` `refresh` refreshes the bookmarks+groups trees up front (`refreshBookmarkTrees()`), then `revalidateOpenDocuments()` → `onFileOpened()` calls `refreshTree()` (= `provider.refresh()`) once **per open document** (`anchor-resolution.ts:167`). So the bookmarks tree is rebuilt `1 + N` times per pulse (N = open editors with anchor state) — O(N) work wasted on workspaces with many open editors.

## Fix
Collapse the per-document refresh into one. Thread an optional `{ deferTreeRefresh?: boolean }` into `onFileOpened`; when set, skip its `refreshTree()`. `revalidateOpenDocuments` passes the flag on the bulk loop and calls `refreshTree()` **once** after the loop (only if ≥1 doc was re-resolved). Per-pulse `provider.refresh()` drops from `1 + N → 1 + 1`. Confined to `anchor-resolution.ts`. The only signature change is an **optional** `opts` param added to `onFileOpened` (on the impl and the public `AnchorResolution` interface) — backward-compatible, so the 4 single-document `onFileOpened` call sites and `ext-context.ts` are untouched and keep their per-call refresh.

Rejected the ticket's alternative (drop the up-front `refreshBookmarkTrees()`): unsafe — `revalidateOpenDocuments` only touches docs that already have state, so a pulse from an MCP add to a non-open file would refresh nothing, and `filesGroups` would stop refreshing on pulse. Preserves the SML-1491 revalidate→refresh→decorate ordering (the batched refresh still follows re-resolution).

## Tests
New `packages/extension/src/anchor-resolution.test.ts` (first coverage for this file), mirroring the `watchers.test.ts` mock harness: mock `vscode` (`workspace.textDocuments`), `@agentic-bookmarks/core`, `./anchorState` (`hasStateForFile`), `./brokenAnchorsSync`; spy `refreshTree`. 4 cases: one refresh for N stateful docs (not N), single-doc `onFileOpened` still refreshes once, `deferTreeRefresh:true` suppresses the refresh, zero stateful docs → no refresh.
