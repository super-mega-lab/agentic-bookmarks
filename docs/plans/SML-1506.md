# SML-1506: Agents panel skill-pill codicons never render (no codiconUri / no font bundled / CSP blocks it)

`renderPill` (`agentsHtml.ts`) emits `<span class="codicon codicon-${skill.icon}">` for each skill pill,
but the codicon stylesheet `<link>` is only injected when `opts.codiconUri` is truthy — and the sole
caller `AgentsViewProvider.render()` never passes it. No `@vscode/codicons` font is bundled and the CSP
(`default-src 'none'; font-src ${cspSource}`) has no `@font-face`, so even a passed URI couldn't load a
font that doesn't exist. Result: every pill shows a missing-glyph tofu box beside its (working) text
label. Purely cosmetic — the label and `runSkill` href still work.

- **Fix (inline-emoji option from the ticket; user-selected):** drop codicons in favor of inline emoji,
  matching this webview's existing inline-glyph convention (`✓`, `⋮`, `?`).
  - `agentsHtml.ts`: change each `SKILLS[].icon` from a codicon name to an emoji (globe→🌐, graph→📊,
    package→📦, file-add→📄, question→❓, bug→🐛); simplify `renderPill` to emit `${icon} ${label}`;
    delete the now-dead machinery — the `codiconUri` option, the `codiconLink` var + `${codiconLink}`
    head injection, and the `.skill-pill .codicon` CSS rule.
  - `agentsView.ts`: no change — it never passed `codiconUri`, so removing the optional option is
    non-breaking.
- **Why not bundle `@vscode/codicons` (the other ticket option):** adds a dependency + build copy-step
  for a Low cosmetic bug, and would be the only codicon usage in the whole webview — inconsistent with
  the file's existing inline-glyph style. Emoji needs no font, no CSP change, and lets us delete code.
- **Tests:** update the renderer suite's per-skill assertion from the `codicon-${skill.icon}` class
  string to asserting the emoji (`skill.icon`) renders, plus that `codicon-` is gone; the 6-pill count,
  runSkill-href, and no-folder (no `skill-pill`) tests stay green. Closes the previously-untested gap
  (old test only checked the class string, never that an icon resolves).
