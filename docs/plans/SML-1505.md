# SML-1505: Agents view skill pills / agent buttons throw "command not found" in a no-folder window

`AgentsViewProvider` is registered in the workspace-**agnostic** activation phase and renders even with
no folder open. Its `render()` unconditionally emits the 6 skill pills (`agenticBookmarks.runSkill`) and
the "Agent connections" section (`buildAgentDescriptors()` returns *all* configured agents, so the
section always shows) — the "Connect to X" buttons (`setupClaude/Cursor/Codex`) and installed-agent
buttons (`agentConnections.*`). All of those commands are registered only inside `activateForWorkspace()`,
which early-returns when no folder is open → clicking any of them throws `command '…' not found`.

- **Fix (Option B from the ticket):** gate the command-bearing affordances on `hasFolder`, mirroring the
  already-shipped `WelcomeViewProvider` pattern.
  - `agentsHtml.ts`: add `hasFolder?: boolean` to `AgentsHtmlOptions` (default `true`). When `false`,
    `renderAgentsHtml` returns a minimal "open a folder" CTA — no skill pills, no agent-connection
    section, hence **no** `command:` URI for any workspace-scoped command. Default `true` keeps the
    ~30 existing renderer tests passing.
  - `agentsView.ts`: `render()` computes `hasFolder` from `workspaceFolders` and passes it (skipping
    `buildAgentDescriptors()` when empty); the constructor subscribes to `onDidChangeWorkspaceFolders`
    (disposable pushed to `context.subscriptions`) so the view re-renders once a folder opens — by then
    `maybeActivateForWorkspace()` has registered the commands.
- **Why not register the commands agnostically (Option A):** invasive/high-regression for a Low bug —
  `registerMcpConfigAndDiagnosticsCommands` needs a large workspace-scoped deps object and `runSkill`
  needs `workspaceRoot` (terminal cwd). The view-gating fix is surgical and aligns the affordances with
  actual command availability.
- **Tests:** add a `renderAgentsHtml — no-folder state` block asserting no `runSkill`/`setup*`/
  `agentConnections.*` URIs and an "Open a folder" CTA + intact HTML/CSP; existing populated-state
  tests stay green.
