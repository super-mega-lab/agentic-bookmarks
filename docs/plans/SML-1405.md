# Implementation Plan: SML-1405

## Ticket
**Delete the icons we will not ship with**

Step 1: Remove icon catalog entries + asset files for everything except Bookmark (standard), Star (standard), Lightbulb, Bug, Todo, Wrench.
Step 2: Change AI-generated default icon from `aiBookmark3` to the Bookmark style.

## Scope Classification
**small** — 5 source files modified, ~37 asset files deleted. All changes are mechanical (literal replacements + file deletions).

## Overview
Purge unshipped icon assets from the extension's media tree, prune their entries from `catalog.json`, and update the three code locations that hardcoded ids/paths belonging to the removed set (`aiBookmark3`, `style1`, `marker-white.svg`) so they reference the canonical `bookmark` style / `bookmark-white.svg` asset.

## Approach Decision

**Approach A (SELECTED): Code-first, assets-second.** Update the four code files that hardcode soon-to-be-removed ids/paths first; then edit `catalog.json` and delete the asset files. This keeps every intermediate commit/state self-consistent — no point during the work has live code pointing at a missing file.

**Approach B: Assets-first, code-second.** Delete files and edit catalog.json first, then fix the code references. Briefly leaves the working tree in a state where decorations.ts/extension.ts/helpers.ts/tools/bookmark.ts reference files or ids that no longer exist.

### Selection Rationale
Approach A — both end states are identical, but A is easier to verify mid-flight (you can typecheck after each unit) and produces a cleaner diff narrative.

### Adaptation Guidance
If during Unit 1 a fifth hidden reference to a removed icon/id surfaces (grep miss), update it the same way: catalog id → `'bookmark'`, asset path → `'media/styles/icons/bookmark-white.svg'`.
