# SML-1556 — inlined/merged detection mixed-base line indexing

**Scope:** small (server). **Type:** Bug. Follow-up to SML-1465 (inlined) / SML-1466 (merged).

## Problem
`detectInlinedConstruct` / `detectMergedConstruct` index the **working-tree** file
(`currentFileLines`, from `fs.readFile`) using **HEAD-relative** diff line numbers
(`cand.newLineNumber`; the diff is `fromCommit → HEAD`). When the working tree has
uncommitted edits **above** the construct (the "user is actively fixing a broken
bookmark" case), `line0 = newLineNumber - 1` indexes the wrong row → a wrong
`mergedInto.line` (merged *computes* the line via `findEnclosingDeclaration`'s
walk-up) or an `inlinedAt.line/content` disagreement. `signature_changed` is
unaffected (no diff coordinates). Every existing fixture sets working tree == HEAD,
so it was untested.

## Fix
Verify-then-trust guards — only index/walk `currentFileLines` when the working tree
actually holds the diff addition at that row. Asymmetric by necessity:
- **inlined** (`inline-detection.ts`): skip a candidate only when `currentFileLines[line0]`
  is **present AND** `!== cand.content`. Absent/out-of-range keeps the documented
  `?? cand.content` fallback — the inline unit tests pass `currentFileLines = []` and
  rely on it, so a strict guard would break them.
- **merged** (`merged-detection.ts`): strict — `continue` unless
  `currentFileLines[line0] === cand.content` before seeding the walk. It never runs on
  an empty file and all fixtures align positions.

Under drift the affected candidate/fragment is dropped; if too few survive the detector
returns `null` and the handler keeps the original `no_match` (conservative decline,
consistent with the modules' "null when ambiguous" design). When working tree == HEAD,
output is byte-identical to before.

## Tests
- `merged-detection.test.ts` +1 unit: drifted `currentFileLines` with a `decoy` method spanning the indexed rows → OLD misattributes `merged → decoy`; NEW → `null`.
- `inline-detection.test.ts` +1 unit: drifted `currentFileLines` whose indexed row ≠ the inlined body → OLD reports wrong content; NEW → `null`.
- `getfilediff-merged.test.ts` +1 e2e (satisfies the ticket's "working tree differs from HEAD"): real repo, uncommitted working-tree file = COMMIT_2 + a `decoyMethod` above `emitData` → NEW → `no_match`, never `decoyMethod`.

## Out of scope
Re-resolving HEAD-relative diff coordinates against the working tree (content search /
relocation). The whole tool inherits the working-tree == HEAD assumption; this fix only
stops emitting *actively wrong* output, per the ticket's framing.
